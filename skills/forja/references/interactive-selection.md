# 交互与目标选择

执行 `init`、选择或切换目标，或处理 Forja 返回的交互字段前，完整读取本文件。

## 阻塞输入

- `questions` 或 `choices` 是阻塞式输入，不是推荐项。立即停止命令链并展示全部待确认
  字段；不得从候选列表、机器检测、历史会话或示例中推断答案。
- 所有 CLI 返回的问题获得用户明确答案前，不得继续命令、创建答案文件或传
  `--answers`。
- `default` 只是候选值，不是用户确认值。

## 提问工具适配

- 每个阶段都重新检查当前提问工具是否可用，以及它对问题数、选项数和自由输入的实际
  限制。不要硬编码工具容量。
- 只有工具能在一次调用中无损承载当前阶段的全部问题、完整 `choices` 和输入语义时才
  使用它；否则用一条普通文本完整展示该阶段。
- 不得拆分、分页、截断或只展示部分 `choices`。不得新增 CLI 未返回的问题字段或实质性
  选项。
- 工具或客户端自动提供的 `Other`、`自定义` 等入口只视为自由输入控件，不是 CLI
  choice；绝不把其占位标签写入答案。工具不能直接返回实际自定义值时，再用普通文本
  仅补录该原问题。
- 输入型问题无 `choices`：工具能保留“候选 default + 自定义输入”语义时可用工具，
  否则用文本索取实际值。
- 混合阶段只有在工具能保留全部原始结构时才整体使用工具；不能承载时，整个阶段降级
  为文本，不要混用两种模式收集选择型问题。
- 某阶段一旦因工具不可用、报错或无法无损承载而降级为文本，保持文本模式直到该阶段
  答案收齐；不要重试工具或拆分阶段。
- 文本模式保留原始 `id`、`label` 和完整 `choices`，不要添加编号或占位选项。若展示
  数量，必须等于实际数组长度。

## 阶段与依赖

- 按语义阶段展示，顺序固定为：⓪ `workroot`（若返回）；① `choicesBy` 父问题；
  ② 对应子问题；③ `mode` 与 Windows `arch`；④ CLI 返回的工具链字段。
- 每个阶段先输出可见标题：
  - `Forja 初始化 — ⓪ 工作根目录`
  - `Forja 初始化 — ① 选择项目分组`
  - `Forja 初始化 — ② 选择项目`
  - `Forja 初始化 — ③ 选择构建参数`
  - `Forja 初始化 — ④ 选择工具链`
  - 切换目标使用 `Forja 目标选择 — ⓪ 选择目标`
  - 后续使用 `Forja 目标配置 — ① 选择构建参数`、
    `Forja 目标配置 — ② 选择工具链`
- 标题只用于展示，不是问题或答案字段。
- `choicesBy` 必须先解决父问题，再根据已选父值完整展示对应子问题。解析为空数组表示
  不适用，不展示、不索取、不写入答案。
- 收到一批答案后，先完成自定义值补录，再按原 `label` 回显实际值，然后进入下一阶段。
- 已确认问题不得重复询问；阶段名不得写入答案。

## 答案文件

- `nextAction` 中的 `<answers.json>` 只是占位符，绝不创建或复用字面量
  `answers.json`。
- 项目已确定时，使用系统临时目录下
  `forja-answers/<SHA-256(规范化项目绝对路径)>.json`；只累积当前目标流程中用户确认的
  字段，不读取或合并其他目标文件。
- 项目未确定时，使用
  `forja-answers/init-<SHA-256(规范化工作根目录或当前目录)>.json`；确定项目后，把本轮
  已确认答案迁移到该目标文件。
- 命令成功或流程取消后删除相应临时文件。
- `workroot` 答案原样写入；不要添加阶段字段。
- 同一字段只提供一次：已写入答案文件的 mode、arch、Qt、VS 或 jom 不要再作为命令行
  参数重复传入。

## 初始化与目标选择

- 新工作根目录或未注册目录使用 `forja init --json`。返回问题时按本文件收集，禁止替
  用户选择有歧义的项目或工具链。
- 选择或切换目标前执行 `forja status --json`，再执行 `forja list targets --json`。
- 默认列表只有一个目标时执行 `forja list targets --all --json` 展开候选；有多个目标时
  先展示默认结果。只有用户选择展示控制项 `未找到，查看全部` 后才执行 `--all`。
- 展示尚未 `--all` 的默认列表时，固定追加唯一的控制项 `未找到，查看全部`。只有提问工具能完整承载所有目标
  加该控制项时才用工具，否则完整文本展示。该控制项只触发 `--all`，不得写入答案或
  作为 `--project`。
- `--all` 返回 `targetGroups` 时两级展示：先用
  `Forja 目标选择 — ① 选择项目分组` 展示全部分组，再用
  `Forja 目标选择 — ② 选择项目` 展示所选组全部目标。分组是展示控制，不写入答案。
- `savedTargets` 中的已保存目标优先用其 `id` 执行
  `forja use target --project <target-id> --json`，只切换 `activeTarget`，不重新询问配置。
  已保存目标的精确路径也只切换目标；新增或未保存路径才进入配置。
- 已初始化工作区切换目标时禁止使用 `forja init`。不带 `--project` 的
  `forja use target --json` 只查看当前目标，不会启动选择。
- 新增目标使用完整项目路径执行 `forja use target --project <path> --json`，并处理后续
  问题。续接时保留原始 `--project`，或完整复制 Forja 返回的 `nextAction`；不要单独执行
  `forja use target --answers ...`，也不要用答案中的 `target` 字段替代 `--project`。
- `mode`、Windows `arch` 和工具链只来自用户确认或同一活动目标的已保存配置。Linux
  当前只有 x64，不询问也不传 `--arch`。
- 只处理 CLI 实际返回的工具链问题：仅返回 `qtPath` 才询问 Qt，仅返回 `vsInstall` 才
  询问 VS，仅返回 `jomPath` 才询问 jom。不要根据机器检测自行新增字段。
- 项目已选但仍有歧义时，只传已确认字段并继续处理返回问题，不要为减少交互自行补齐。
- 环境候选使用 `forja list env --json`，不要用 `init` 代替。
