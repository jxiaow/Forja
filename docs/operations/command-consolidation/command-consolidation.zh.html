Command Consolidation

Forja 命令收敛迁移方案

这是一版中文可读的 HTML 方案。核心目标是把原来的 Qt、SDK、Remote、Sync 命令树，收敛为 10 个面向用户意图的命令，同时保留底层能力用于兼容和内部复用。

总览

最终用户只需要理解这一组命令：

forja status
forja init
forja list
forja use
forja build
forja run
forja stop
forja clean
forja doctor
forja sync

这里不再把 qt、sdk、remote 放在第一层命令里。它们变成当前目标的属性：当前目标是 Qt 还是 SDK、执行端是本地还是远程，由 forja use 选择，由其他命令自动读取。

重要结论：不是删掉能力，而是把能力从“模块树”收敛成“用户意图”。用户说“构建”，就执行 forja build；至于它背后是 Qt build、SDK build、remote Qt build，交给 active target 和 runAt 决定。

核心模型

Active Target：当前目标

activeTarget 是 Forja 当前正在操作的对象。所有执行类命令都围绕它工作。

interface ActiveTarget {
  kind: 'qt' | 'sdk';
  project: string;
  mode: 'debug' | 'release';
  arch: 'x86' | 'x64';
  runAt: 'local' | 'remote';
}
  • kind 表示当前目标是 Qt 还是 SDK。
  • project 是当前项目文件，尽量保存为相对 workspace 的路径。
  • mode 和 arch 是用户共同理解的构建配置。
  • runAt 表示执行端：local 是本机，remote 是远程流水线。
  • 如果一个仓库同时有 Qt 和 SDK，Forja 不能猜，必须通过 forja use 明确选择。

Candidate：可选目标

候选目标来自现有扫描能力：Qt 扫描 .pro，SDK 扫描 .sln 或 Makefile。forja list 只负责列出来，不负责修改配置。

runAt：执行端

本地和远程不再是两套命令。用户通过下面命令选择当前目标在哪里执行：

forja use --local
forja use --remote

选择远程后，forja build、forja run、forja clean 等命令会自动走远程准备、远程执行和远程诊断流程。

逐命令流程

forja status

用途：回答“当前是什么状态，下一步该干嘛”。它必须轻量、只读、快速，不做深度 SSH 或完整工具链探测。

流程

  1. 解析 workspace。
  2. 读取 active target。
  3. 读取 Qt、SDK、Sync、Remote 设置摘要。
  4. 如果没有 active target，检查是否存在候选目标，但不自动选择。
  5. 如果有 active target，检查项目文件是否存在、mode/arch 是否有效、执行端是否配置完整。
  6. 输出当前目标、同步状态、远程状态、运行状态和下一步命令。

示例

forja status
forja status --json
forja status --workspace C:\repo

边界

  • 混合仓库没有当前目标时，不猜 Qt 还是 SDK，提示 forja list 和 forja use。
  • 远程配置缺失时，不尝试 SSH，只提示如何选择服务器和远程路径。
  • ps 这类运行状态归入 status。

forja init

用途：第一次使用时自动检测和初始化。它只写入可以自动确定的配置，不做模糊选择。

流程

  1. 扫描 Qt 候选目标。
  2. 扫描 SDK 候选目标。
  3. 检测 Qt、VS、jom、make 等工具链。
  4. 保存明确无歧义的工具链默认值。
  5. 如果整个 workspace 只有一个目标，则保存为 active target。
  6. 如果同时有 Qt 和 SDK，或有多个目标，不选择，提示 forja list 和 forja use。

示例

forja init
forja init --plan
forja init --remote
forja init --json

边界

  • init 不接受 --project、--mode、--arch 这类显式选择参数，这些属于 use。
  • --remote 只处理远程初始化或 bootstrap 这类准备工作，不替用户选择目标。

forja list

用途：回答“有哪些可选项”。它是只读命令，不修改任何配置。

分类

forja list
forja list targets
forja list env
forja list servers
forja list remote-repos

流程

  1. 默认列出 targets。
  2. targets 包含 Qt 的 .pro 和 SDK 的 .sln / Makefile。
  3. 标记当前 active target。
  4. 标记每个候选是否已配置完整。
  5. list env 显示工具链候选。
  6. list servers 显示服务器，不显示密码。

边界

  • 没有目标时，提示 forja init。
  • 服务器详情不存在时，列出可用 server id。

forja use

用途：唯一的选择和配置入口。目标、mode、arch、本地/远程、服务器、远程路径，都由它负责。

示例

forja use
forja use --target apps/client/client.pro
forja use --target sdk/NemoSDK.sln
forja use --kind qt
forja use --kind sdk
forja use --mode release --arch x64
forja use --local
forja use --remote
forja use --server dev --remote-path /home/dev/workspace

流程

  1. 无参数且是交互终端时，展示目标选择、模式选择、执行端选择。
  2. 有参数时，只更新显式提供的字段。
  3. --target 根据文件类型推断 Qt 或 SDK。
  4. --kind 只有在该类型只有一个候选目标时才自动切换，否则提示 forja list。
  5. --remote 和 --local 只切换执行端。
  6. 完成后提示 forja status。

边界

  • --target 不能指向 workspace 外部。
  • 非 Windows 平台拒绝不支持的 arch。
  • 远程缺 server 时，不偷偷创建配置，提示 forja list servers。

forja build

用途：构建当前 active target。它统一处理 Qt、SDK、本地和远程。

示例

forja build
forja build fresh
forja build qmake
forja build rcc
forja build --plan
forja build --json

模式

命令Qt 目标SDK 目标
forja build必要时 qmake/rcc，然后 build。正常 build。
forja build freshclean + qmake + rcc + build。rebuild 或 clean + build。
forja build qmake只跑 qmake。明确报错：当前 SDK 目标没有 qmake 步骤。
forja build rcc只跑 rcc。明确报错：当前 SDK 目标没有 rcc 步骤。

流程

  1. 读取 active target。
  2. 没有 target 时返回 forja list 和 forja use。
  3. Qt local：调用现有 Qt qmake/rcc/build 能力。
  4. SDK local：调用现有 SDK build/rebuild 能力。
  5. remote：先远程 preflight，再准备 workspace，再调用远程 Qt/SDK action。
  6. fresh、qmake、rcc 是互斥的 build 子动作。

forja run

用途：运行当前目标。Qt 支持运行，SDK 默认没有运行语义。

示例

forja run
forja run --detach
forja run --json

流程

  1. 读取 active target。
  2. Qt local：必要时构建，然后运行。
  3. Qt remote：远程准备后执行 remote run。
  4. SDK：返回“不支持 run”，下一步提示 forja build。
  5. --detach 返回 pid 和 logFile。

forja stop

用途：停止当前运行目标。

流程

  1. 读取 active target。
  2. Qt local：调用本地 stop。
  3. Qt remote：调用远程 stop。
  4. SDK：返回“没有可跟踪运行态”。
  5. 没有运行记录时，返回 not-running，不视为严重错误。

forja clean

用途：清理当前目标构建产物。

示例

forja clean
forja clean --plan
forja clean --json

流程

  1. 读取 active target。
  2. Qt local：调用 Qt clean。
  3. SDK local：调用 SDK clean。
  4. remote：远程 preflight 后调用远程 clean。
  5. --plan 只展示计划，不删除产物。

forja doctor

用途：深度诊断。它比 status 慢，可以检查工具链、SSH、远程 Forja、路径、权限和 remote workspace。

示例

forja doctor
forja doctor --remote
forja doctor fix
forja doctor fix --remote
forja doctor --json

流程

  1. 读取 active target 和所有设置。
  2. 检查本地工具链。
  3. 检查 sync 配置。
  4. 在 remote 已选中或传入 --remote 时检查 SSH、remote Forja bin、remote workspace。
  5. 输出修复建议，建议必须使用新命令。
  6. fix 只做非破坏性修复，例如 bootstrap；不能静默执行 restore/reset/clean-untracked。

危险恢复动作

这些动作不能做普通命令，需要显式参数和清晰提示：

forja doctor unlock <lock-id> [--force]
forja doctor restore <repo> <paths...>
forja doctor reset <repo> <paths...>
forja doctor clean-untracked <repo> <paths...> [--recursive]

forja sync

用途：同步变更文件。它保留为顶层命令，因为“同步”本身就是用户目标。

保留用法

forja sync
forja sync plan
forja sync --file src/main.cpp
forja sync --repo app
forja sync reset
forja sync --json

迁移

  • sync use 移到 forja use --server ... --remote-path ...。
  • sync servers 移到 forja list servers。
  • sync test-connection 移到 forja doctor。
  • server 增删改、transfer 配置、build-order 这类低频配置不进入 sync 子命令树；状态由 status 展示，检查由 doctor 承接，配置优先走 use 的高级流程或迁移期兼容入口。

实现分阶段

阶段 1：新增统一模型，不改变现有行为

  • 新增 active target 类型和读写 helper。
  • 新增 Qt/SDK candidate 聚合。
  • 写混合仓库测试：有 Qt + SDK 时不自动选择。
  • 旧命令完全不动。

阶段 2：实现 status/list/use/init

  • 在顶层 CLI dispatcher 增加新命令路由。
  • 实现只读 status。
  • 实现只读 list。
  • 实现显式选择 use。
  • 实现保守初始化 init。
  • 把旧 nextActions 改成新命令。

阶段 3：实现执行命令

  • 实现 build 路由。
  • 实现 build fresh。
  • 实现 build qmake 和 build rcc。
  • 实现 run、stop、clean。
  • 接入远程执行端。
  • 更新 VSCode 状态栏和 action menu。

阶段 4：实现 doctor 和整理 sync

  • 聚合本地工具链、sync、remote 诊断。
  • 把连接测试迁到 doctor。
  • 保留 sync 的执行能力。
  • 更新 sync 帮助文档，弱化 server/config 子命令。

阶段 5：隐藏兼容入口

  • 隐藏旧 VSCode 命令面板入口。
  • 保留旧 command ID。
  • 文档只展示新命令。
  • AI skill 文档改用新命令。

阶段 6：验证与打包检查

  • 运行 npm run compile。
  • 运行统一 CLI 相关测试。
  • 运行 npm test。
  • 运行 npm run build:cli，确认 CLI 包包含新模块。
  • 除非明确发布，不运行 npm run package:all。

兼容策略

  • 第一阶段实现后，旧 CLI 子命令仍然可执行。
  • 旧 VSCode command ID 不删除、不重命名。
  • 旧命令不再出现在主要 help、nextActions、QuickPick 和 Command Palette。
  • 旧命令在文本模式可以提示“推荐使用新命令”，JSON 输出不要加入噪音。
  • 第二个版本仍然保留旧命令执行能力，除非明确决定做破坏性清理。

最终决策

  • remote 不作为顶层用户命令。
  • qmake 和 rcc 不作为顶层用户命令。
  • Qt 阶段能力通过 forja build qmake 和 forja build rcc 保留。
  • status 轻量只读。
  • doctor 深度诊断。
  • list 只读列举。
  • use 是唯一普通配置入口。
  • init 只做自动初始化，不做模糊选择。
