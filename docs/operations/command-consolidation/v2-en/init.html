forja init

Responsibility: First-time initialization. Detects toolchain paths and saves unambiguous configuration without making fuzzy choices on behalf of the user. Safe to re-run.

Syntax

forja init [--workspace <path>] [--remote] [--plan] [--json]

Behavior

  1. Scan Qt targets (.pro files).
  2. Scan SDK targets (.sln/Makefile).
  3. Discover available toolchain paths (Qt/VS/jom/make) for saving defaults — path discovery only, no health validation (health validation belongs to doctor).
  4. Save toolchain defaults (Qt path, VS path, jom path).
  5. Save mode/arch defaults. Mode defaults to release; arch is platform-dependent (Windows defaults to x86, other platforms default to x64).
  6. If the entire workspace has only one target, save it as the active target.
  7. If multiple targets or mixed Qt+SDK, do not select; next actions point to forja list + forja use.
  8. If zero targets, only save toolchain defaults; next action points to forja list.
  9. --remote executes initialization on remote via bridge. Requires configured server; if remote lacks Forja bin, next action points to forja doctor fix --remote.

Idempotency

Safe to re-run. Already-saved user choices are not overwritten; only missing items are filled in.

--plan

Outputs "what will be detected, what will be saved" without writing configuration.

Absorbed Commands

forja qt init, forja sdk init, forja remote qt init, forja remote sdk init

Not Absorbed

forja remote bootstrap (deploy Forja bin) → forja doctor fix --remote

Result

interface InitResult extends ForjaJsonResult {
    action: 'init';
    mode: 'local' | 'remote';
    detected: {
        qtTargets: number;
        sdkTargets: number;
        toolchain: { qt?: boolean; vs?: boolean; jom?: boolean; make?: boolean };
    };
    saved?: { mode?: string; arch?: string; toolchain?: string[] };
    ambiguous?: boolean;  // true when multiple targets or mixed Qt+SDK
    plan?: CommandPlan;
}

Implementation Details

--remote Bridge Command Construction

forja init --remote executes remote init via executeRemoteBridge for each detected target kind (qt/sdk):

cd <remotePath> && <remoteForjaBin> <target> init --workspace <remotePath> --json
  • <target>: qt or sdk, determined by the detected target kinds. If an activeTarget exists, only its kind is used. Otherwise defaults to qt.
  • <remoteForjaBin>: From RemoteSettings.remoteForjaBin, defaults to $HOME/.forja/bin/forja.
  • Timeout: Default 120 seconds (consistent with bridge default).
  • If the remote Forja binary is not found (exit 127/126), returns an error pointing to forja doctor fix --remote.

ActiveTarget Storage

When a single target is automatically saved, activeTarget is stored at:

~/.forja/projects/<workspace-hash>/activeTarget.json

Format:

{
    "kind": "qt",
    "project": "app/app.pro",
    "mode": "release",
    "arch": "x86",
    "runAt": "local"
}

Also writes to legacy settings file for backward compatibility (pinnedProject field in ~/.forja/projects/<workspace-hash>:qt.json).

ok Determination Rules

  • When mode: 'local':
    • Configuration write successful → ok: true (even if toolchain is missing, zero targets, or multiple targets)
    • Configuration write failed → ok: false
    • --kind mismatch with scan results → ok: false
  • When mode: 'remote':
    • Any error-level diagnostic → ok: false
    • Bridge execution successful and remote returns ok: true → ok: true
    • Bridge execution failed or remote returns ok: false → ok: false
  • Warning-level diagnostics do not affect ok value
  • info-level diagnostics are for information only and do not affect ok value
