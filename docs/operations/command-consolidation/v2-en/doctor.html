forja doctor

Responsibility: Deep diagnostics and recovery. Slower than status, responsible for checking toolchains, sync, SSH, remote Forja, and workspace. All "does it work?" questions go to doctor.

Public Syntax

forja doctor [--remote] [--workspace <path>] [--json]
forja doctor fix [--remote] [--workspace <path>] [--json]
forja doctor unlock <lock-id> [--force] [--workspace <path>] [--json]

Hidden Syntax (destructive operations, not in main help)

forja doctor restore <repo> <paths...> [--workspace <path>] [--json]
forja doctor reset <repo> <paths...> [--workspace <path>] [--json]
forja doctor clean-untracked <repo> <paths...> [--recursive] [--workspace <path>] [--json]

Standard Check Categories

  • toolchain-qt — Qt installation detection (qmake availability)
  • toolchain-vs — Visual Studio detection (MSBuild availability)
  • toolchain-jom — jom detection (parallel build tool)
  • toolchain-make — make detection
  • target — active target validity
  • sync — sync configuration completeness
  • remote — SSH connection, remote Forja bin, workspace (only when runAt=remote or --remote)

Behavior

  1. Check active target.
  2. Check local toolchains (Qt/VS/jom/make).
  3. Check sync configuration.
  4. When runAt=remote or --remote, check remote.
  5. fix only allows non-destructive repairs (including cleanup of residual config, bootstrap remote Forja bin, initialize local state directory).
  6. unlock releases remote lock, --force to force.
  7. restore/reset/clean-untracked are destructive operations, must be passed explicitly, not auto-executed by doctor or fix.

Absorbed Commands

forja sync test-connection, forja remote test, forja remote doctor, forja remote bootstrap (→ doctor fix --remote), forja remote unlock, forja remote qt restore/reset/clean-untracked, forja remote sdk restore/reset/clean-untracked, forja cleanup (→ doctor fix)

Result

interface DoctorResult extends ForjaJsonResult {
    action: 'doctor';
    doctorAction: 'check' | 'fix' | 'unlock' | 'restore' | 'reset' | 'clean-untracked';
    checks?: CheckResult[];
    changed?: string[];
}

interface CheckResult {
    name: string;
    status: 'ready' | 'blocked' | 'warning' | 'skipped' | 'unknown';
    message?: string;
    diagnostics?: Diagnostic[];
    nextActions?: string[];
}
