forja sync

Responsibility: Synchronize changed files to remote. Kept as a top-level command because sync is an independent user goal.

Syntax

forja sync [--workspace <path>] [--file <path>] [--repo <name-or-path>] [--json]
forja sync plan [--workspace <path>] [--file <path>] [--repo <name-or-path>] [--json]
forja sync reset [--workspace <path>] [--json]

Behavior

  1. Read sync configuration.
  2. When server/remote path is missing, fail without attempting SSH; return forja list servers + forja use --server.
  3. plan only outputs the plan.
  4. --file limits synced files (repeatable).
  5. --repo limits repo or overrides single-repo remote path.
  6. reset only clears state, does not upload.
  7. If artifact transfer is configured, sync can perform transfer after normal sync; sync plan only shows summary.

Removed from Main Help

forja sync use, forja sync servers, forja sync server, forja sync add-server, forja sync update-server, forja sync remove-server, forja sync test-connection

Server CRUD is retained as compatibility commands during migration. New users do not encounter server CRUD through sync.

Result

interface SyncResult extends ForjaJsonResult {
    action: 'sync';
    syncAction: 'run' | 'plan' | 'reset';
    plan?: SyncPlan;
    server?: string;
    remotePath?: string;
    uploaded?: string[];
    deleted?: string[];
    skipped?: string[];
    transfer?: {
        configured: boolean;
        planned?: boolean;
        executed?: boolean;
        artifacts?: string[];
    };
}

interface SyncPlan {
    mode: 'dryRun';
    server: string;
    remotePath: string;
    repos: string[];
    pending: string[];
    deleted: string[];
    skipped: string[];
    skippedDetails?: Array<{ file: string; reason: string }>;
}
